# 扎根理论编码工作台

本技能提供扎根理论编码的详细操作指引。全局的研究背景、阶段判断参见 grounded-theory 技能（在 available_skills 列表中查找）。编码工作表的详细格式参见 `references/coding_sheet_format.md`。

项目特定的研究问题、编码焦点维度定义在项目目录的 `CLAUDE.md` 中。本技能启动时应读取该文件获取项目上下文。

## 阶段1：主题簇浏览与文本选取

**数据细读的顺序策略：**

数据有两个维度：主题（BERTopic主题簇）和时间（时间戳）。不同的阅读顺序会带来不同的分析收获。建议采用组合策略：

**第一轮：按主题簇深读（建立概念框架）**
- 选取3-5个与研究问题最相关的主题簇
- 每个主题簇内选取10-30条代表性文本（高概率典型文档、边界文档、异常文档）
- 在同一主题簇内做深度初始编码，目标是充分发展该主题下的概念维度和属性
- 这一轮结束后，你应该有了一个初步的概念框架

**第二轮：按时间线抽样（检验概念稳定性与变化趋势）**
- 选取同一主题簇在不同时间段的文本（如：某事件发生初期 vs. 三个月后 vs. 热度消退期）
- 检验第一轮建立的概念是否在时间维度上稳定
- 关注时间带来的变化——参与者对研究对象的理解是否随时间推移而演化？早期和后期的表达方式是否不同？
- 时间维度的发现可能揭示现象的过程性，这对研究问题往往有重要价值

**后续轮次：理论抽样驱动**
- 根据前两轮涌现的概念和空白，有针对性地选取数据
- 可能的方向：搜索包含特定隐喻或关键概念的主题簇、选取与核心范畴高度相关的主题簇、选取负面评价或抵抗性叙事

**当研究者提供主题簇数据时：**
1. 帮助研究者浏览主题簇的关键词和代表性文档
2. 讨论哪些主题簇与研究问题最相关
3. 协助从每个关注的主题簇中抽取代表性文本
4. 建议理论抽样策略——不只看"典型"，也关注"意外"和"边缘"
5. 如果研究者提供了主题随时间的变化趋势数据，帮助识别关键时间节点（如某主题突然增长或分裂的时刻），这些节点是理论抽样的优先目标

**输出：** 将选取的文本整理到工作文档中，附带来源主题簇编号和选取理由。

## 阶段2：文本细读与初始编码（Initial Coding）

这是Charmaz方法的核心起点。对选取的文本逐段进行贴近数据的编码。

**操作方式：**
1. 研究者提供一条或多条文本
2. 先整体浏览文本，把握语境和整体叙事
3. 然后逐段（或逐个意义单元）进行编码
4. 编码尽量使用动名词（gerund）形式，保持动态感（如"协商身份"而非"身份"）
5. 每个编码附带简短的分析性说明

**关键原则（来自Charmaz）：**
- 保持对数据的开放，不过早收敛
- 使用"体内编码"（in vivo codes）——保留参与者自己的语言
- 提问：这段数据在说什么？参与者在做什么？他们如何理解自己的行动？
- 关注过程（process）、行动（action）和意义（meaning）

**编码时的对话姿态：**
- 对每段文本，先给出你的编码建议，但明确标注为"初步解读"
- 主动提出替代编码的可能性
- 问研究者："这个编码是否捕捉到了你感受到的核心张力？"
- 如果研究者的编码与你不同，探讨差异的原因——差异本身就是分析资源

**围绕研究问题的编码焦点：**

编码时围绕项目 `CLAUDE.md` 中定义的研究问题展开。通用的编码关注维度包括：
- 参与者用什么**隐喻**或**类比**来描述研究对象？
- 意义建构是如何发生的？是预设的还是互动中形成的？
- 参与者的**预设**是什么？预设如何被打破或重构？
- 数据中是否有参与者**显性比较**不同对象的片段？

具体的研究问题相关编码维度参见项目 `CLAUDE.md`。

**编码格式示范（供初学者参考）：**

以一条文本为例，编码过程如下：

> 原文示例："今天跟风试了个新工具 但是并不知道能干啥 有点茫然"

| 要素 | 内容 |
|------|------|
| **初始编码** | 跟风试探未知事物 |
| **编码类型** | 过程编码（动名词形式） |
| **分析性说明** | "跟风"表明行动是社交驱动而非需求驱动；"茫然"暗示认知距离 |
| **替代编码** | 无目的地遭遇新事物 |
| **关联研究问题** | 参见 CLAUDE.md 中的研究问题 |

这个格式帮助你：(1) 保持编码的动态感（动名词），(2) 追溯编码的理由，(3) 始终回扣研究问题。

## 阶段3：聚焦编码（Focused Coding）与概念提炼

**操作方式：**
1. 回顾所有初始编码，识别反复出现的模式
2. 将相关编码归纳为更高层次的概念范畴
3. 对每个聚焦编码/概念，撰写操作性定义
4. 用持续比较法检验：新数据是否仍然适用？是否需要修改？

**怎么判断哪些编码有"更强的分析力"？**
- **频率**：在多条不同的文本中反复出现（但注意：频率高不一定分析力强，频率低也可能很有理论价值）
- **覆盖面**：能够统摄多个其他初始编码。比如一个过程性编码可以统摄多个描述具体事件的初始编码
- **与研究问题的关联度**：直接回应研究问题的编码优先提升
- **分析的深度**：能够揭示"过程"或"机制"的编码比仅仅描述"现象"的编码更有分析力。例如"将话语转化为情感资源"比"保存记录"更有分析力，因为前者揭示了一个意义建构的过程

**怎么撰写操作性定义？**

操作性定义回答一个问题：如果另一个研究者拿到这个编码，她能不能准确判断哪些数据属于这个编码、哪些不属于？

模板：[概念名称] 指的是 [行动者] 在 [什么情境下] 通过 [什么方式] [做什么/经历什么]，其特征包括 [关键特征]，与 [易混淆概念] 的区别在于 [区别点]。

例如："预设的瓦解"指的是参与者在与研究对象互动过程中，原有的认知框架被实际体验打破的过程。其特征包括：(1) 存在明确的"之前"认知状态；(2) 一个具体的转折事件；(3) 伴随强烈的情感反应（惊讶、困惑等）。与"渐进式认知更新"的区别在于瓦解具有突然性和情感冲击性。

## 阶段4：备忘录撰写（Memo-writing）

备忘录是扎根理论的"引擎"。贯穿整个过程，而不仅是某个阶段。

**什么时候该写备忘录？** 以下都是信号：
- 你对一个编码犹豫不决（犹豫本身值得记录和探索——为什么犹豫？）
- 你突然想到两个编码之间可能有联系（哪怕很模糊，写下来！）
- 你读到一条数据时感觉"这跟之前那条好像但又不太一样"（比较的直觉是宝贵的）
- 你发现一条数据让你惊讶或不舒服（情感反应往往指向重要的分析线索）
- 你读了一篇文献后想到"这个概念好像能解释我看到的现象"（文献对话的起点）
- 编码做了一段时间后感觉"卡住了"或"混乱了"（写备忘录本身就是整理思路的过程）

不需要等到有"完整的想法"才写。备忘录就是用来捕捉半成型想法的——写给自己看的思考草稿。

**备忘录的协作模式：**

备忘录不是Claude独自撰写的，也不需要研究者独自完成。协作方式如下：

*研究者负责（不可替代）：* 核心判断和直觉（"我觉得这两个编码之间有张力"）、分析决策的理由（"我选这个编码是因为..."）、反思性的部分（"我的预设可能是..."）——这些模糊的、身体性的感受恰恰是备忘录最有价值的原材料。

*Claude负责：* 把研究者口语化、碎片化的表达整理成结构清晰的分析性文字；补充研究者提到但没有展开的比较；按模板格式化，确保关联编码、关联数据、待追问的问题等字段不遗漏；在研究者的思路基础上提出追问。

*流程：* 研究者提供思想的种子 → Claude扩展为结构化备忘录草稿 → 研究者审核确认或修改。

**备忘录的自动触发：**

Claude根据对话中的信号**主动**判断何时该生成备忘录，研究者无需明确指示"撰写备忘录"。

Claude应主动生成备忘录草稿的场景：
- 研究者表达了分析性洞察（如"我觉得这两个编码之间有关系"）
- 研究者对编码产生犹豫或分歧（如"我不确定该叫什么"）
- 一轮编码结束后，过程中积累了值得记录的讨论
- 研究者表达了情感反应或惊讶（如"这条数据很有意思""这让我想到..."）

Claude不应主动生成的场景：
- 研究者正在专注编码，节奏顺畅——不应打断
- 讨论内容是事务性的（如"帮我把这个表格整理一下"）

触发时，Claude在回复末尾附上备忘录草稿，并简短提示"根据我们刚才的讨论，我整理了一份备忘录草稿，你看看是否准确捕捉了你的想法"。研究者确认后，Claude将备忘录保存为Markdown文件到 `memos/` 对应子目录。研究者可以确认、修改、或说"先不管备忘录，继续编码"——Claude应尊重研究者的节奏。

研究者也可以随时主动触发，说"写个备忘录"或"把刚才的讨论记录下来"。

**备忘录类型：**
- **编码备忘录**：解释某个编码的含义、适用范围、与其他编码的关系
- **理论备忘录**：探索概念之间的关系、提出初步理论命题
- **过程备忘录**：记录分析决策和反思（为什么选这个编码？为什么放弃那个？）
- **文献对话备忘录**：将涌现的概念与已有文献对话（详见 gt-literature 技能）

**备忘录模板：**

```markdown
# [备忘录标题]

- **类型**: 编码备忘录 / 理论备忘录 / 过程备忘录 / 文献对话备忘录
- **日期**: YYYY-MM-DD
- **关联编码/概念**: [列出相关编码]
- **关联数据**: [引用相关数据片段的ID]

## 内容

[备忘录正文——分析性写作，不是描述性总结]

## 待追问的问题

- [分析中浮现的问题和方向]

## 下一步

- [具体的分析行动]
```

## 框架收束与编码手册（深度编码→批量编码的过渡）

这是从深度编码进入批量编码前的**必经环节**。目的是把散落在编码表、备忘录、snapshot 中的分析洞察收拢为一份结构化的编码手册，同时暴露框架的薄弱点。

### 何时触发

满足以下条件时，由 Main Agent 或研究者发起：
- 已深度编码 2 个以上主题簇
- 聚焦编码数量达到 15+ 个
- 理论备忘录积累 3+ 篇
- 新概念涌现频率明显下降（从"每 5 条出 2 个新面向"降至"每 10-15 条偶尔出现"）

不要求所有条件同时满足——如果研究者感觉"差不多都在重复了"，就可以启动。

### 操作流程

#### 第一步：汇编——把散落的概念集中

读取以下所有文件，提取全部聚焦编码和概念：
- `coding/focused/` 中的所有聚焦编码表
- `coding/initial/` 中初始编码表的"分析简注"列
- `memos/coding/` 所有编码备忘录
- `memos/theoretical/` 所有理论备忘录
- 最新 snapshot 中的"核心概念清单"

输出一份**概念清单草稿**，列出所有已命名的聚焦编码和跨主题概念。

#### 第二步：写操作性定义——把直觉变成规则

对每个聚焦编码写出：

```markdown
### [编码名称]（如"预设的瓦解"）

**定义**：一句话说明这个编码捕捉的是什么现象。
**判断标准**：数据中出现哪些特征时编码为此？（列 2-3 条可操作的判断规则）
**典型案例**：1-2 条代表性数据片段（附来源）
**边界案例**：容易混淆的情况，以及如何区分
**与其他编码的区别**：与哪些编码容易混淆，区别在哪里
```

**写不出来的地方就是框架还不稳的地方**——标记为"待补充"，这些是后续需要更多数据的方向。

#### 第三步：画关系——编码之间怎么连接

整理编码之间的层级和关系：
- 哪些编码属于同一个上位范畴？
- 哪些编码之间是条件关系（A 出现时 B 倾向于出现）？
- 哪些编码之间是张力/矛盾关系？

用简单的层级列表或 Mermaid 图表示。不需要完美，能看出结构就行。

#### 第四步：跨主题验证——框架能不能 hold 住

从每个已编码的主题簇中各取 5-10 条**之前编过的**数据，用编码手册草稿重新编码：
- 手册定义能覆盖这些数据吗？
- 是否需要修改定义？
- 是否发现之前遗漏的编码？

再从**未编码的**主题簇中取 5-10 条新数据试编：
- 框架对新数据的适用性如何？
- "存疑"比例是多少？

#### 第五步：判断——稳了吗？

| 指标 | 可以进入批量编码 | 还需要继续深度编码 |
|------|:---:|:---:|
| 操作性定义完成率 | ≥80% 编码有清晰定义 | 多个核心编码写不出定义 |
| 跨主题验证 | 旧数据重编结果基本一致 | 大量需要修改 |
| 新数据试编存疑率 | <15% | >30% |
| 编码间关系 | 主要关系已明确 | 核心关系仍模糊 |

如果判断"还不稳"，回到深度编码，带着明确的问题继续（"我需要更多 X 类型的数据来厘清 Y 编码的边界"）。这就是**理论抽样**。

### 输出文件

编码手册保存为 `coding/codebook_draft_v{版本号}.md`，包含：
1. 所有聚焦编码的操作性定义
2. 编码层级/关系图
3. 跨主题验证结果
4. "待补充"清单（框架薄弱点）
5. 是否进入批量编码的判断及理由

## 框架辅助批量编码（第三层）

**前提：已完成上述框架收束环节，编码手册草稿经研究者审核。**

当初步概念框架建立后，可以让Claude用已有框架做批量编码。

**具体操作流程：**

1. **研究者准备数据**：将待批量编码的文本整理为CSV或Excel文件上传（必须包含列：数据ID、主题簇、原文、时间戳），每批建议50-100条
2. **研究者提供编码框架**：将已建立的聚焦编码表（含操作性定义）提供给Claude作为编码依据
3. **Claude执行批量编码**：对每条文本逐条编码，输出包含以下列的Excel表格：数据ID、原文片段、匹配的聚焦编码、置信度（高/中/低）、分析简注、存疑标注
4. **研究者审核**：重点审核置信度为"中"和"低"的编码、所有"存疑"标注、以及Claude标注的负面案例
5. **修正与反馈**：研究者修正后的结果反馈给Claude，用于改进后续批次的编码一致性

批量编码时Claude应该：
- 严格使用已建立的编码框架，不自行创造新编码
- 对无法归入现有编码的数据片段标注"存疑"，供研究者审核
- 记录编码分布的统计概况（每个编码出现频次、各主题簇的编码分布）
- 标注可能的负面案例（与现有概念矛盾的数据）
- 每批编码完成后，生成一份简短的"编码反思"：是否发现现有框架的盲区？是否有反复出现但无法归类的现象？

如有 xlsx skill 可用，读取其 SKILL.md 并遵循其规范来创建结构化表格。

## 持续比较法的实践

持续比较是扎根理论的方法论灵魂。在每个阶段都应实践：

- **数据与数据比较**：这条文本和那条文本有什么相似和不同？
- **数据与编码比较**：这个编码是否适用于新的数据？
- **编码与编码比较**：这两个编码是否实际上在说同一件事？
- **编码与概念比较**：这个初始编码属于哪个更高层的概念？
- **概念与概念比较**：这两个概念之间是什么关系？

当研究者提供新数据时，主动将其与已有编码和概念进行比较，而不是孤立地分析。

## 社交媒体数据的方法论考量

社交媒体文本作为研究数据有独特的方法论考量，分析时需持续反思：

- **表演性（performativity）**：社交媒体帖子是写给公众看的，参与者的叙事方式受平台文化影响。编码时需要区分：参与者真正的体验 vs. 平台化的表达方式——但也不能简单二分，因为表演本身也是意义建构。
- **标签（hashtag）作为数据**：帖子中的标签是参与者自己对内容的归类和框架，是极有价值的分析材料——它们暴露了参与者如何为自己的经验赋予意义。
- **平台作为中介**：社交媒体平台本身在意义建构中扮演角色，分析时需考虑平台特性对数据的影响。
- **短文本的密度**：社交媒体文本通常较短但信息密度高，每条可能浓缩了一个完整的叙事弧线。编码时注意这种叙事结构本身的分析价值。
- **多模态**：很多帖子包含图片/截图。如果研究者提供了图片内容的描述，将其纳入分析范围。

项目 `CLAUDE.md` 中可能包含特定平台的额外分析要点。
